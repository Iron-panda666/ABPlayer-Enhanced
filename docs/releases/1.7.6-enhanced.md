# ABPlayer Enhanced 1.7.6

## Automatic backup before updating

When an existing Fork profile is present, setup creates a complete profile archive **before replacing installed program files**, including during repair/reinstall. A first installation without a Fork profile has nothing to back up.

1. Quit the player normally so it saves its listening position. Setup waits for the application to close; it does not terminate playback.
2. Setup snapshots library metadata, positions, bookmarks, covers, preferences, tiers and statistics into an `.abplayer-backup` file.
3. The archive is flushed to disk, read back and validated using the restore format. If backup fails, setup stops before replacing program files.
4. After a successful snapshot, retain the newest **3 automatic backups**. Only marked automatic archives are eligible for cleanup. Manual archives and unrelated files remain untouched. If an older archive is locked and cannot be removed, leave it in place rather than discard the new backup or block an otherwise protected update.
5. Continue the in-place application update.

Automatic archives are stored in:

```text
%APPDATA%\com.ironpanda666.abplayer-backups
```

The filename includes the target app version and a unique snapshot identifier. Backup files stay local and do not include audiobook audio files. Keep those separately.

## Restoring an automatic backup

Open **Library → … → Backup and restore → Choose backup to restore**. The dialog displays the automatic backup location and initially opens that folder when it exists. Select an archive, review it and choose **Restore on next launch**. The current profile is kept as a safety copy when restore is applied.

Automatic backups are outside the live profile, so normal uninstall and its optional profile deletion do not remove these archives. The automatic backup folder can contain private library information and is excluded from the public source tree.
